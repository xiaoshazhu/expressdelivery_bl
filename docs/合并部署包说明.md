# 边栏插件与字段捷径：宝塔合并交付包

`上传宝塔部署包.zip` 把两个服务放在独立目录，方便一次上传和解压。它不是单个 Node 项目；宝塔需要分别运行两个 Node 项目，不能把 `field/` 的文件覆盖到 `sidebar/`。

## 已看到的宝塔目录（2026-10-09 截图）

宝塔文件管理器显示现有站点目录为 `/www/wwwroot/express-delivery`，里面已有边栏服务的 `dist/`、`public/`、`server/`、`vendor/`、`package.json` 和 `.env`。2026-10-08 的边栏 v2 ZIP 在这里，`dist/` 与 `server/` 的修改时间紧随其上传时间；这支持“已解压”的判断，但不能证明 Node 项目已重启。截图没有显示 2026-10-09 的字段捷径支付后端文件。

因此**不要把本包的 `field/` 内容直接解压到 `/www/wwwroot/express-delivery` 根目录**。这会覆盖现有 `server/index.mjs`、`package.json`、`public/pay.html` 等文件。可以把字段捷径服务放在例如 `/www/wwwroot/express-delivery-field` 的独立目录，但还需核对宝塔 Node 项目的启动目录、端口和网站反向代理，才能让现有字段捷径访问该服务。

| 目录 | 内容 | 用途 |
| --- | --- | --- |
| `sidebar/` | 宝塔现有边栏服务的完整部署包，叠加截图所示 2026-10-08 的 v2 更新；不混入字段捷径支付改动 | 边栏页面和原有接口 |
| `field/` | 2026-10-09 字段捷径真实微信支付后端 | 字段捷径额度、收银台、支付回调 |
| `飞书字段捷径上传包.zip` | 2026-10-08 已生成的飞书字段捷径代码包；本次支付修改只在后端，此包未改动 | 仅用于字段捷径中心上传，不在宝塔解压 |

## 部署前核对

1. 在宝塔记录当前站点的根目录、Node 项目目录、启动命令、端口和反向代理规则；备份当前部署目录、线上 `.env`、证书和数据库。
2. 将 `sidebar/` 和 `field/` 解压到**不同**的目录。各自在对应目录安装依赖，并各自配置 `.env`。ZIP 不含真实 `.env`、商户私钥或微信支付公钥。
3. 为两个 Node 服务配置不同端口。建议字段捷径服务只监听 `127.0.0.1` 的独立端口，并将它当前使用的 `express-delivery.anhuishuzhi.com` 域名反向代理至该端口。边栏服务使用其现有独立域名或另一个域名。
4. 两边都有 `/pay`、`/api/pay/...`、`/api/health` 等同名路径。如果必须共享同一个域名，先设计明确的路由前缀并同时修改字段捷径前端 URL、支付页面请求、支付回调地址和边栏入口。**不要简单合并两个目录或只切换 `/pay` 路由。**
5. 字段捷径后端的线上 `.env` 除商户凭证外，还需要 `WECHAT_PAY_PUBLIC_KEY_ID` 与 `WECHAT_PAY_PUBLIC_KEY_PATH`；后者指向微信支付公钥文件，不能指向商户私钥。`WECHAT_NOTIFY_URL` 必须指向字段捷径服务的公网 HTTPS 回调路径。修改 `.env` 后重启字段捷径 Node 项目。
6. 用真实租户打开字段捷径收银台并做一笔小额支付，核对订单只入账一次；同时检查边栏原有查询和收银台。不要用演示二维码判断真实支付已上线。

字段捷径中心上传的 `output/output_*.zip` 与本包不同。此次微信支付改动在宝塔后端，单独上传边栏插件的飞书前端包不会更新字段捷径支付功能。

当前无法访问宝塔项目配置，也无法确认线上实际运行了哪一份 ZIP。本包只整理并隔离文件，不会自动部署或修改线上反向代理。
