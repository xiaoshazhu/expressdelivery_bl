# 付费与计费接入

当前边栏插件已按参考项目的“套餐配置 → 企业授权 → 使用扣减 → 退款幂等”模型接入基础计费能力。

配置 `MCP_BILLING_URL` 与 `MCP_BILLING_TOKEN` 后，余额、成功扣次、支付下单、支付回调、订单查询和退款全部转发到外部 MCP/平台账本；插件只传递业务元数据，不再本地维护余额账本。

## 已接入

- 根目录 `packages.json`：100 次、1000 次和 365 天订阅三个示例套餐。
- `GET /api/plugin/billing/config`：平台读取套餐配置。
- `POST /api/plugin/billing/update`：平台校验并原子更新套餐文件。
- `POST /api/plugin/license/sync`：平台下发企业授权最终值，覆盖保存，不累加。
- `POST /api/plugin/order/refund`：订单退款状态幂等处理。
- `POST /api/billing/payment-callback`：支付成功回调，重复回调按订单号幂等处理。
- `POST /api/billing/order-status`：查询订单状态。
- `POST /api/billing/refund`：测试环境退款入口。
- `POST /api/billing/status`：边栏读取当前表格的套餐状态。
- 真实或模拟查询成功后按 1 次扣减额度；格式错误、手机号缺失、无轨迹等不会扣次。
- 扣次携带稳定的幂等键，同一记录和单号的重复执行不会重复扣次。

平台接口使用 `Authorization: Bearer <API_TOKEN>`，前端和飞书授权码都不会接触该 Token。

## 启用扣次

开发环境默认只展示套餐状态，不强制拦截查询。上线前在服务端 `.env` 配置：

```env
BILLING_CONFIG_PATH=./packages.json
BILLING_ENFORCE=true
API_TOKEN=替换为高强度随机值
```

然后由管理平台调用 `license/sync` 下发每个企业的 `tenant_key`、额度或到期时间。当前飞书表格的 `appToken` 作为插件本地租户标识；正式接入管理平台时应改为可信的 `tenant_key`，不能让浏览器自行传入。

## 动态金额与字段捷径

支付金额始终由服务端按 `plan_id` 从套餐配置读取，浏览器不能提交任意金额。普通收款与字段捷径可以使用不同的支付入口，通过 `payChannel` 和 `MCP_*_PATH` 配置区分。字段捷径调用 `/api/license/check-and-consume` 时应传递稳定的 `idempotencyKey`，否则无法判断重复触发。

## 支付渠道边界

参考目录中的支付宝/微信证书属于敏感私钥，本项目没有复制到仓库，也没有把密钥放进前端。测试环境可调用微信 Native 下单、查单、模拟支付和回调；配置 MCP 后，支付订单、回调、退款会转发给外部账本。真实微信回调上线前仍需在支付网关完成签名验签，并将验签后的标准订单事件转发到 `/api/billing/payment-callback`。
