## 2. 已确认的技术事实

- 官方后端 README 明确：personalBaseToken 从 Base 插件 UI 中 Custom Plugin → Get Authorization Code 获取。[来源](https://github.com/Lark-Base-Team/lark-base-mcp-node-server#tokens)
- Node SDK 的 BaseClient 使用 appToken 和 personalBaseToken；不要求企业自建应用参数。[来源](https://www.npmjs.com/package/@lark-base-open/node-sdk)
- 官方前端模板可作为边栏插件起点；本项目沿用 React、TypeScript、Vite 与官方 JS SDK 的技术结构，界面和业务重新实现。[来源](https://github.com/Lark-Base-Team/react-template)
- 官方 JS SDK 文档提供字段、记录和分页读写 API。当前已核对 SDK 类型，但没有找到可直接绑定原生按钮点击的完整公开 API；这不等于宣称飞书平台永远不支持。[来源](https://lark-base-team.github.io/js-sdk-docs/zh/api/table)

## 3. 上架路径

目标是“多维表格边栏插件市场”，不是让每个客户在开放平台创建一个企业自建应用。

官方发布页描述了发布代码/运行地址并通过表单提交、由官方联系协助上架的路径。[发布插件](https://lark-base-team.github.io/js-sdk-docs/zh/start/release)

当前公开页仍含 Replit 的历史操作界面，因此不能把其每个按钮与步骤视为最新后台操作。官方 React 模板还链接以下开发指南：

- [多维表格插件开发指南](https://bytedance.feishu.cn/docx/HazFdSHH9ofRGKx8424cwzLlnZc)
- [官方发布页引用的表单](https://bytedance.feishu.cn/share/base/form/shrcnfhuWeBHoWTicKLFybn92Lb)

本次工具无法读取前述飞书文档正文，也未验证表单现时可提交。需在正式提审前由开发者登录官方入口核对：最新提交方式、开发者资质、授权码收集是否符合审核要求、托管方式、语言/主题、收费规则、素材规格和隐私材料。**技术上无需企业自建应用，不意味着已获得上架许可或免审核。**

## 4. 实施里程碑

| 阶段 | 交付 | 出口条件 |
|---|---|---|
| M0 方案与 Demo | 本项目源码、文档、模拟查询 | 本地测试和交互验证通过 |
| M1 飞书联调 | 授权码、字段和记录读写、原生按钮 | 用户测试表中单行和批量均通过 |
| M2 真实物流 | 阿里云市场快证适配、异常映射、核验参数 | 五类承运商用真实测试单逐一通过 |
| M3 商业化工程 | 租户隔离、加密凭证、队列、专用工作流凭证 | 重启/撤销/并发/限流/费用验收通过 |
| M4 提审 | HTTPS 生产服务、介绍、截图/视频、隐私说明、客服资料 | 符合当期审核要求，官方审核通过 |

当前完成 M0；M1 的接入代码已提供但未真实验证；M2 已改为阿里云市场快证接口并完成协议级自动化测试，等待用户配置该商品AppCode并用真实运单验收。没有执行公网部署或提交审核。

## 5. 提审材料准备建议

以下为项目准备清单，不冒称未经核对的强制审核条款：

- 名称：运单助手；简介：单条与批量查询物流信息并回写多维表格。
- 说明哪些承运商支持真实查询，货拉拉等自定义名称如何手工处理。
- 安装、启用飞书授权码、字段映射、配置按钮、批量查询的演示素材。
- 数据处理说明：授权码的用途/保存期限/撤销方式、发给物流商的数据范围。
- 隐私政策、用户协议、客服和故障处理入口，由运营主体定稿。
- 生产地址、版本记录、测试账号或按官方要求提供的审核测试条件。
- 在目标飞书环境验证窄边栏、主题变化和当前要求的语言范围；本 demo 尚未实现多语言和主题跟随。
