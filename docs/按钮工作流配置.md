# 原生按钮列工作流配置

状态：设计与后端接口已完成；尚未在用户真实飞书租户创建或运行工作流。

## 1. 为什么需要工作流

边栏里的 React 按钮可以直接调用查询接口。飞书表格中的原生“按钮”是平台能力，不能给普通文本单元格塞入 HTML onClick，也不能将选中单元格事件假装成点击按钮事件。

推荐方案：原生按钮触发工作流，工作流发送 HTTP 请求，获得结果后修改触发记录。这保留三列结构，并可在边栏关闭时运行。飞书官方资料介绍了自动化中的 HTTP 请求动作；官方 CLI 的工作流参考也区分表格按钮 buttonField 与页面按钮。[HTTP 动作说明](https://www.feishu.cn/content/article/7581775868524104882)、[工作流按钮触发器参考](https://github.com/larksuite/cli/blob/main/skills/lark-base/references/lark-base-workflow-schema.md)

**以上是架构依据，不等于当前租户已完成验证。** 管理员权限、套餐、HTTP 响应映射和平台 UI 以实际租户为准。

## 2. 字段和步骤

1. 在测试表中准备「快递单号」「快递信息」两个文本字段。
2. 新增「查询快递」按钮字段，按钮文案为“查询”。
3. 建立一个以“点击按钮时”为触发器的工作流，选择当前数据表和该按钮。
4. 添加发送 HTTP 请求动作，POST 到自己的 HTTPS 查询后端 `/api/workflow/query`。
5. 设置 JSON 请求体，单号使用触发记录的字段变量；承运商按固定配置、自动识别或可选第 4 列引用。
6. 成功分支：读取响应 `resultText`，通过“修改记录”仅更新**触发记录**的「快递信息」。
7. 失败分支：保持旧信息，记录失败原因或通知操作者；不要用错误响应覆盖旧轨迹。
8. 启用后验证同一表中不同按钮只改变各自所在行；关闭边栏后再次验证。

工作流运行期间用户可能编辑单号。生产配置建议在更新前重新检查当前单号是否仍等于触发时单号；否则放弃写回。工作流更新路径与后端 query-record 路径不同，不能自动继承后端的冲突检查。

## 3. 请求和响应

HTTP Header：

```text
Content-Type: application/json
Authorization: Bearer <工作流凭证>
```

Body 示意（实际 UI 中请插入字段变量，而不是照抄尖括号文本）：

```json
{
  "number": "<触发记录.快递单号>",
  "carrier": "自动识别"
}
```

成功响应：

```json
{
  "number": "JD002938475610",
  "carrier": "京东",
  "mock": true,
  "summary": "【模拟数据】京东 · 运输中 · 快件已到达分拨中心",
  "queriedAt": "2026-09-15T05:00:00.000Z",
  "resultText": "【模拟数据】京东 · 运输中 · 快件已到达分拨中心\n查询时间：2026-09-15T05:00:00.000Z",
  "events": []
}
```

工作流 HTTP 动作如何暴露响应对象必须以实际界面查看；业务 JSON 字段是 `resultText`，不要未经验证硬编码 `data.body.resultText` 等外层路径。

## 4. 本地接口验证

本地服务启动后，先创建一个只查询模拟物流的演示会话：

```sh
curl -s http://127.0.0.1:8787/api/connect \
  -H 'Content-Type: application/json' \
  -d '{"mode":"demo"}'
```

把返回的 token 用于下一请求（不要填飞书 personalBaseToken）：

```sh
curl -s http://127.0.0.1:8787/api/workflow/query \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <上一步返回的token>' \
  -d '{"number":"JD002938475610","carrier":"京东"}'
```

该演示 token 一小时有效，进程重启或断开连接会失效；它验证的是 HTTP 协议，不是长期生产鉴权。飞书云工作流无法访问开发者机器的 127.0.0.1，真实联调必须准备可访问的 HTTPS 测试环境。

## 5. 正式凭证设计

正式版不得将飞书个人授权码直接填入工作流请求头；应由后端生成专用工作流凭证，绑定安装/表格、限定物流查询权限、支持撤销、轮换、限额和审计。工作流只负责读取本行输入并更新本行结果。若后端还需直接写表，须单独设计受限写回权限。

没有在此任务中创建公网域名、后台凭证管理系统或真实工作流。客户不需要自建企业应用，但表格所有者需要按模板完成一次按钮工作流配置；能否随表格模板复制后保留工作流、是否还需重设凭证，要在目标租户验证。
