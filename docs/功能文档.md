# 运单助手功能文档

版本：0.1 / 日期：2026-09-15 / 定位：面向插件市场上架的 Demo 和实施方案。

## 1. 产品目标与范围

用户通过飞书自定义插件入口打开插件，自动识别当前数据表，粘贴当前多维表格的授权码，建立运单查询字段。单条查询通过表格按钮完成，批量查询通过边栏完成。客户无需创建企业自建应用。

本需求中的“授权码”已由用户明确为 **多维表格 → 自定义插件 → 获取授权码** 中启用和复制的码，技术名称为 personalBaseToken。它用于访问飞书表格，与物流接口密钥无关。[官方授权码说明](https://github.com/Lark-Base-Team/lark-base-mcp-node-server#tokens)

“生成一列快递单号”指创建一个供用户填写的文本字段，不包含下单、电子面单或生成承运商有效运单号码。

## 2. 用户流程

1. 从插件市场安装运单助手（上架目标；当前尚未发布）。
2. 在当前多维表格启用授权码，填入插件。
3. 由前端获取或用户填写 appToken、tableId，后端验证授权。
4. 创建/复用「快递单号」「快递信息」两列；配置已有字段时要求两列均为文本且不同。
5. 在飞书添加第三列「查询快递」按钮，关联工作流。
6. 填写真实单号；如混合承运商不能可靠识别，可采用第 4 节的扩展字段方案。
7. 点击本行按钮查询并更新信息；或边栏中一键查询全部记录。

默认 `/` 必须在飞书边栏中使用。独立测试入口 `/?demo=1` 可跳过真实飞书连接，使用本地六行数据体验交互。

## 3. 三列核心数据结构

| 字段 | 类型 | 用途 | 当前 Demo 状态 |
|---|---|---|---|
| 快递单号 | 文本 | 存放运单号，保留字母和前导零 | 可自动创建/复用；真实单号由用户填写 |
| 快递信息 | 多行文本 | 汇总状态、最近轨迹、查询时间 | 可自动创建/复用，成功查询后写回 |
| 查询快递 | 飞书原生按钮 | 对本行执行查询工作流 | 需人工创建和绑定；插件界面提供等效逐行按钮 |

边栏页面中的三列表格是交互预览，不是将普通 HTML 按钮嵌进飞书单元格。公开 SDK 没有经本项目确认的原生按钮点击回调或完整工作流创建接口，不能承诺仅靠 SDK 一键生成并绑定原生按钮。

## 4. 承运商规则

- 当前真实查询适配器：阿里云市场快证快递查询，固定接口为 `https://kzexpress.market.alicloudapi.com/api-mall/api/express/query`。
- 鉴权采用阿里云云市场 APPCODE 简单认证。AppCode 仅保存在服务端；AppKey/AppSecret 为另一套签名认证方式，当前代码预留配置但不读取。
- 请求字段：`expressNo` 为单号；`mobile` 为核验手机号；`cpCode` 为快递公司编码。不传 `cpCode` 时由供应商自动识别。
- 批量混合承运商建议新增“快递公司”文本列，填写中文常用名或所购商品文档中的 `cpCode`。非主流及海外快递建议显式填写编码。
- 阿里云模式下，顺丰、中通和跨越需要完整 11 位收/寄件手机号或后四位。建议新增“核验手机号”文本列。
- 货拉拉是否支持取决于该阿里云商品的 cpCode 清单；未取得明确编码和真实结果前按人工物流处理。
- Demo 行内承运商编辑仅保存在内存，位于单号下方；它用于说明交互，不代表飞书文本字段保存了复合结构。
- 详细的数量口径、公司清单入口、购买和费用见《真实物流接口与支持范围》。

## 5. 功能明细

### F01 授权连接

- 默认飞书边栏模式，自动识别当前 Base、数据表和选中行；仅独立测试页提供模式切换。
- appToken、tableId 自动识别，用户只输入 personalBaseToken，密码框遮蔽授权码。
- 后端通过读取指定数据表字段验证，失败不签发会话。
- 输入框连接成功后清空；后端通过随机会话令牌引用 SDK 客户端，最长保留一小时。
- 不存入 localStorage、表格字段、URL、仓库或日志。断开时删除会话；服务重启后需要重新输入。
- Demo 会话不是商业授权/计费机制。

### F02 字段初始化

- 先扫描同名字段及类型；发现类型冲突则提示手动映射。
- 同名文本列复用，不改名、不清空已有数据。
- 创建过程中若第二列失败，已创建列保留，重试时复用，避免重复建立。
- 原生按钮列依照工作流文档配置，属于待人工接线部分。

### F03 单行查询

- 单号去除首尾空格，按实时查询接口校验为 6–32 位字母、数字、连字符。
- 请求前禁用重复点击；成功后刷新信息和轨迹面板。
- 飞书模式由后端按绑定表读取记录，使用表中当前单号查询，不信任前端传入的单号。
- 写回前再读取单号和旧信息，发生变化则放弃写回并提示重试。
- 对 SDK 没有原子条件更新能力的场景，读后写仍存在极小竞争窗口；正式版需设计写回协调，不能宣称完全杜绝并发覆盖。

### F04 一键批量查询

- “全部”定义：点击查询后重新读取的当前数据表内、授权码可读的全部记录，包含当前视图筛选隐藏记录，不跨数据表、不绕过权限。
- 后端分页遍历全部数据；实际边栏只显示进度和最近轨迹，不复制整个飞书表格。独立测试页每页展示 20 条。
- 查询按快照逐条执行，间隔 550ms，空单号跳过；查询开始后的新增记录需下一次查询才纳入。
- 显示完成进度、成功数、失败数、跳过数；单条失败继续后续项。
- 停止仅取消尚未发起的查询，已发请求与已写回记录不会回滚。
- 失败重试仅处理当前列表中的失败记录；已有结果不会因为查询失败被清空。
- 同一服务进程内，相同承运商、单号和核验手机号的成功结果缓存 30 分钟；重复点击返回缓存，不再次请求供应商。
- 当前批量调度在浏览器，关闭边栏会停止后续调度。生产目标若要求关闭后继续，必须改为后端任务队列。

### F05 人工物流

货拉拉等未适配承运商保留原来人工填写的信息，显示“当前没有轨迹接口”而非虚假运输状态。人工更新在飞书信息列完成。

## 6. 原生按钮方案

推荐链路：原生按钮 → 飞书工作流 → HTTP 查询后端 → 工作流更新触发记录。

此链路不依赖边栏保持打开，且无需企业自建应用；但正式凭证、公开 HTTPS、工作流权限、HTTP 响应取值能力及当前套餐限制均需真实租户验证。Demo 已实现查询接口与 JSON 契约，未自动在飞书创建工作流。

## 8. 上架前产品决策

确认物流服务商、是否允许第 4 列承运商、商用计费主体、是否要求后台持续批量、数据保存期限及客服入口。当前不会要求客户配置企业自建应用。

## 9. 飞书宿主行为

入口 `/` 在 iframe 内启动官方 SDK，自动获取表名与当前选中记录；跟随选区变化。在飞书中切换数据表时停止后续查询并清除旧会话，新的表需重新授权。已发出的请求仍可能在原表完成。非 iframe 打开则展示添加插件步骤。宿主 10 秒未响应会提示重新识别；不会自动切入模拟数据掩盖宿主连接失败。
